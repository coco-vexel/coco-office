# Security reports

Do not put unpatched vulnerabilities, private documents or credentials in public
issues. Use GitHub's **Security → Report a vulnerability** when private reporting
is enabled. If that control is unavailable, contact a repository maintainer
privately; do not post the exploit in a public issue.

Include the affected version, a minimal synthetic reproducer, impact and relevant
runtime details. There is no published response-time SLA during this pre-release
phase. Maintainers must enable and verify private vulnerability reporting before
making the repository public.
